# Providers

Playbook ships adapters for five agent CLIs. Each adapter can, in code, drive tasks as the **main agent** (under the same hooks) and/or serve as a **judge** on the review panel — but *support* is scoped by capability. As of the 2026-08-21 owner decision:

- **Claude Code** — supported as both the **main agent** and a **judge**. It is the only provider whose hooks gate a live coding agent in supported use.
- **Grok** and **Codex** — supported as **judges** (live-verified 2026-08-22). Their main-agent *enforcement* paths ship but are **experimental** (adapter code retained, no support claim, no live evidence).
- **Antigravity** — **experimental** everywhere, with no support claim. Its judge path was rewritten for agy 1.2.17 and measured on one Linux account on 2026-10-05, and re-measured on agy 1.3.1 on 2026-10-07 with no change needed ([notes](#provider-notes)); its main-agent path has no live evidence.
- **Pi** — **experimental** everywhere. The adapter code ships and is retained, but there is no support claim and no live evidence.

Antigravity and Pi keep their adapter code and carry no support claim; Pi has no live evidence, and Antigravity's judge path has the one-account measurement described in the notes below.

## Provider notes

The support tier above governs the claim; the notes below describe the shipped mechanism, which is retained in all cases.

- **Claude Code** (`claude`, native) — reference platform; hooks registered by the plugin. Only judge with a budget cap (`judge_budget_usd`).
- **Codex** (`codex`, `playbook-codex`) — **judge: supported** (live-verified 2026-08-22). **Main agent: experimental** — `apply_patch` edits are gated via dedicated codex hooks (codex pre-blocks `apply_patch` edits but not file writes made through plain shell commands). Effort levels `low…ultra` per the model cache. Business-plan runs can be slow — raise the review timeout if judges expire.
- **Grok** (`grok`, `playbook-grok`) — **judge: supported** (live-verified 2026-08-22). **Main agent: experimental** — relies on always-trusted global hooks: `tasks init --provider grok` writes `~/.grok/hooks/playbook-enforcement.json` (task-gate + state-echo + chat-log), required on spaced project paths (iCloud) where project/plugin hooks never schedule. Restart Grok after install/upgrade. Project hooks still need `/hooks-trust` once. Payloads normalized by shared shim: camelCase keys, `Shell`→Bash, `StrReplace`→Edit, plus `write`→Write, `search_replace`→Edit, `run_terminal_command`→Bash. `grok models` is an account-entitlement list. Web search on by default (judges pass `--disable-web-search` when off).
- **Antigravity** (`agy`, `playbook-agy`) — **judge: experimental; main agent: experimental.** Google's Antigravity CLI, and the route to a Gemini judge paid by a consumer subscription: the `gemini` CLI refuses a personal Google login (0.62.0, the owner's attempt on 2026-10-05 answered "This client is no longer supported for Gemini Code Assist for individuals … migrate to the Antigravity suite of products") and otherwise takes an API key. The **judge path** was rewritten for agy 1.2.17 and measured on 2026-10-05 on one Linux machine with a Google AI Pro sign-in (task 111), and re-measured on agy 1.3.1 on 2026-10-07 (task 130): ten 1.3.1 captures made with the same commands, and every test of the judge path run over them with 1.3.1's own token counts (the cases 1.3.1 could not be made to produce — a real quota stop, a web tool call, a signed-out run, a model/effort conflict, two constructed streams — replay their 1.2.17 capture). No support claim follows from one machine; what was measured:
  - *Prompt on stdin.* One NDJSON line (`--input-format stream-json`, no `-p`), so a judge prompt has no argv size cap — a 150 KB prompt arrived whole — and the seat gets the stdin context budget.
  - *Pinned model.* A seat is `agy:<id>`, e.g. `agy:gemini-3.8-flash-high` — a whole id as `agy models` lists it; the id carries the effort, and the `<base>:<effort>` form other providers use is refused. agy rejects an id it does not know before any turn, and its output echoes the model value it accepted: a pinned seat whose output carries another value, or none, fails. (That echo is agy's word for what the session was started with — the seat cannot observe the serving model any other way.)
  - *Read-only is the OS sandbox, not agy's plan mode.* `--mode plan` is passed, but under the bypass flag every judge runs with it did not stop a file write in our test — the sandbox's read-only project bind did. Where no OS sandbox is usable (no usable `bwrap`, a nested sandbox) the agy judge is uncontained like every other judge and the tamper guard is the only defence.
  - *Sign-in used in place.* agy keeps its credential in the OS keyring (reached over the session D-Bus) and its state in `~/.gemini`; the sandbox uses both where they are — nothing is copied. The judge never hands `GEMINI_API_KEY`, `GOOGLE_API_KEY` or `GOOGLE_APPLICATION_CREDENTIALS` to agy: the seat is for a signed-in subscription, not per-call or per-project billing (so an agy signed in through Application Default Credentials cannot serve as this seat).
  - *Usage.* The turn's `input_tokens` / `output_tokens` go into the review-spend journal, one record per call.
  - *Failures the seat names.* Not signed in, quota exhausted, a rejected model selection: the cause is the first line of the failed seat, read only from the four places agy itself states an error — its `error:` and `AGY_ERROR:` stderr lines, its result's error field and the error of a response step — for every exit code (agy's log lines and a tool's own error are not a cause). A failed seat with no named cause leads with everything agy stated. Output that is not agy's event stream is never accepted as a review. A real quota stop looks like this: agy exits 3 after the turn has already run for minutes, with `Individual quota reached. … Resets in 34m13s.` — the seat's first line carries that sentence, and the tokens spent before the stop are still recorded. Four ways agy exits 0 without a review are each a failed or timed-out seat — its own `--print-timeout` expiry (exit 0, `status: SUCCESS`, partial text, no token usage — that shape is never taken for a finished turn; but when agy also states an error, the seat fails with that error instead of "timed out"), a tool request that headless mode auto-denies (empty response), an error mid-turn, and a web or browser tool call while web search is off (agy has no flag that disables those tools, so the seat is told not to use them and its output is checked).
  - *Not measured.* An expired sign-in and a depleted AI-credit balance (handled from agy's documented messages, with tests on constructed output that say so); more than 15 calls in 5 rounds of 3 at once.

  *Live check (2026-10-05, that one machine):* a one-seat agy panel and a single-judge review each returned a review of a scratch project, wrote nothing in it, and left one spend record whose token counts equal the ones agy printed for the call; `tasks models set` / `detect` / `check` ran against the same account. *On agy 1.3.1 (2026-10-07, same machine):* `tasks models check` answered OK, and the seat sat in four six-seat implementation panels: three returned their review, one failed with agy's own "The stream was interrupted" as its named cause and its partial findings kept. That is one account on one platform — the seat stays experimental.

  `tasks models check` probes an agy pin with one tiny real turn and prints the remaining quota and AI credits. The **main-agent path** (hooks through `agy plugin install`, `GEMINI.md`, the session-log reader) was written for agy 1.0.2, was not touched by that work, and has no live evidence.
- **Pi** (`pi`, `playbook-pi`) — **experimental everywhere.** Ships a hook adapter (`playbook-pi-hook-adapter.ts`) and a local models file (`playbook-pi-omlx-models.json`). An argv-length guard refuses a judge prompt too big for one argument (Linux caps one at 128 KB on 4 KB pages) before the call.

## Launchers

The `playbook-*` wrappers (installed to `.claude/bin/` by `/playbook:init`) start each CLI with a unique per-session Playbook session ID (PID-based, provider-agnostic), so gate state, chat-log attribution (`claude`/`codex`/`agy`/`grok`/`pi` tags), and multi-agent handoffs work identically everywhere. Each wrapper provisions its session directory in the [per-user lane](architecture.md#per-user-lanes) — the same one the hooks and the `tasks` CLI read — and refuses to launch rather than guess when a repo has lanes but no `.agent/current_user` marker. (The launchers exist for all four non-Claude providers; only their judge use on Grok and Codex is a supported claim.)

## How the same hooks run everywhere

The plugin registers six lifecycle hooks once (see [architecture](architecture.md)); non-Claude providers reach them through provider adapters (`provider/adapters/*.py`) plus, where needed, a payload-normalization shim that translates each CLI's event schema to the Claude one. The edit gate ("no active task → no code edits") *runs* under every provider in code, but **supported enforcement is Claude-only** — the grok and codex enforcement paths are experimental, and antigravity/pi are experimental everywhere. Two provider-specific caveats on the experimental paths: codex pre-blocks `apply_patch` edits but not file writes made through plain shell commands, and **Grok** relies on always-trusted `~/.grok/hooks/playbook-enforcement.json` (project/plugin hooks need `/hooks-trust` and still may not schedule on spaced paths).

## Judges across providers

Judge-seat support covers **Claude, Grok, and Codex** (live-verified 2026-08-22); Antigravity and Pi judge seats are experimental. Panel seats are specs like `codex:gpt-5.6-terra:high`, `grok:grok-4.6` or (experimental) `agy:gemini-3.8-flash-high` in [`.agent/models.json`](configuration.md). Each provider adapter knows how to run its CLI headless (prompt on argv vs stdin, model/effort splitting, context inlining) and how to classify failures. Pin health is maintained with `tasks models check` / `select` — including probe-confirmed hard stops when a pinned model disappears from your account, which is a when, not an if.
